# Plano de implementação — Fase 1 (inscrição, atividades, e-mail)

Spec: `../specs/2026-11-02-credenciamento-design.md`. Entrega incremental; cada etapa é testável sozinha.

## Estrutura
- `apps-script/` — backend (Apps Script ligado à planilha): `Config.gs`, `Db.gs`, `Setup.gs`, `Inscricao.gs`, `Atividades.gs`, `Email.gs`, `Admin.gs`, `Api.gs`, `Qrcode.gs` (biblioteca MIT qrcode-generator).
- `inscricao/` — `index.html` (inscrição no evento) e `atividades.html` (link pessoal), `config.js` (URL do Web App).
- `assets/` — logos e CSS (identidade visual).
- `tests/run.js` — testes em Node com simulação de SpreadsheetApp/MailApp/LockService.

## Decisões técnicas
- **Fila de e-mails (aba `Fila_Email`)**: toda mensagem vira uma linha PENDENTE; é enviada na hora e, se falhar ou faltar cota, um gatilho de 10 min reenvia (prioridade: confirmação > promoção > fila > atividade). Só o organizador é avisado.
- **Alertas ao organizador em resumo** (no máximo 1 e-mail a cada 30 min) para poupar a cota do Gmail.
- **Segurança**: duplicidade por matrícula nunca devolve o token na tela (só reenvia ao e-mail cadastrado, mascarado na resposta); `inscricoes` começa FECHADAS; PIN fica só na planilha.
- **POST como `text/plain`** para o front-end no GitHub Pages falar com o Web App sem preflight de CORS.
- **QR**: gerado no navegador e no Apps Script (mesma biblioteca), sem serviço externo; o QR contém apenas o token.
- Nomes de abas sem acento (`Inscricoes_Atividades`) para evitar erro em fórmulas.

## Etapas
1. Esqueleto + `Setup` (cria abas, cabeçalhos, Config, programação) + testes.
2. Inscrição no evento (validação, duplicidade, fechadas) + e-mail + fila de e-mail + alertas + gatilho.
3. Atividades: abrir/fechar, vagas, conflito, fila de espera, promoção automática, cancelamentos.
4. Front-end: `inscricao/index.html` (tela de sucesso com QR) e `atividades.html` (link pessoal).
5. Roteiro de publicação (Apps Script + Pages) e teste real.
6. (Fase 2) Scanner e permanência.
